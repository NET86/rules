# 维护与自动化

`main` 保存开发与候选版本，`stable` 提供订阅，`last-known-good` 用于恢复。输入文件职责见[来源与策略](SOURCES.md)，命令与检查边界见[验证说明](VALIDATION.md)。

## 更新与失败

授权范围内自动更新，新授权候选隔离待审。**保留旧版必须有有效基线**：生产输入无基线时阻止发布；官方事实无基线仅标记不可用。

| 情况 | 处理 |
| --- | --- |
| V2Fly 抓取、解析或许可检查失败 | 保留旧快照，冻结该来源的删除观察；语音仍可更新。 |
| 显式选择项消失或移入 include | 报告异常，仅冻结相关厂商的删除观察；仍须满足覆盖校验。 |
| 语音抓取失败或覆盖变化可疑 | 保留旧 IP；域名仍可更新。 |
| 官方抓取或解析失败 | 按来源保留有效事实，不冒充新事实，不阻断其他来源。 |
| 普通上游规则消失 | 满足退役条件后删除；同厂商的有效后缀已完整覆盖时可直接删除冗余项。 |
| 关键覆盖消失 | 保留待审，不能自动删空厂商或破坏厂商、合集语义契约。 |
| 本地授权撤销 / drop | 立即撤销；retention 不能复活，也不能替其他规则提供覆盖。 |
| 校验或发布失败 | 不提升未验证候选；已提升但回读失败时尝试向前提交恢复 `stable`，未恢复则后续运行继续检查。 |

退役须同时满足：**14 个日历日、3 个不同 UTC 日期的健康观察、本次观察健康**。异常不增加观察次数，也不暂停日历时间。`--allow-reviewed-removals` 可跳过等待天数和观察次数，但不绕过本次健康与覆盖保护。阈值在 `automation.json`。

语音新增地址族、覆盖扩大超过 4 倍或原覆盖保留不足一半需审核；等价 CIDR 拆分、合并不算异常。批准新基线后用 `python scripts/sync.py --voice-file <官方JSON>` 更新，再完整验证。

OpenAI 资料的 403 仅对固定公开 URL 尝试锁定的 HTTPS 兼容传输。同步中依赖安装失败不阻断其他来源；CI 仍严格检查依赖。抓取未恢复不能靠关闭 Issue 消除异常。

## 发布

先验证或恢复 `stable`，再刷新输入，通过单元、产物、语义与双内核检查。候选进入 `main` 后按不可变 SHA 回读；通过后原子更新 `stable` / `last-known-good`，再验证稳定订阅。

远端引用变化时拒绝覆盖并报错。恢复不回退 `main`。产物与产品契约不变时不轮换 `stable`，但证据和观察状态仍可更新到 `main`。因此 `main` 上的文案或代码修改不会立即出现在 `stable`；只有产品契约变化并完成整套发布验证后，发布流程才会把当前候选的完整文件树提升到 `stable`。

修改输入后运行 `python scripts/rules.py`，再[完整验证](VALIDATION.md)。固定内核升级必须重跑双内核三种配置，不能只验证下载成功。

## 调度与异常

同步每 6 小时，官方与混合分类雷达随同步，Sukka 每周；示例客户端每小时拉取订阅。[Cloudflare 主调度与 GitHub 兜底](../infra/scheduler/README.md)中，Cloudflare 固定触发；GitHub 每天 `00:31` 检查最近一轮带 Cloudflare 标记的运行，只有该次运行已完成且成功才跳过兜底。

工作流先上传 `.work/` 证据，再更新异常 Issue，最后生成只读摘要。摘要分开报告作业、发布和恢复结果；规则变化比较候选与上次 `stable`，未发布的候选变化不代表生效。恢复预检写 `recovery-report.json`，真正发布写 `release-report.json`。

Issue 未变不重复写入，重现则重开，消失后关闭。过大正文只展示摘要，以完整异常指纹识别变化；完整报告在 artifact。缺失或无效报告不能用于关闭；环境尚未就绪或被取消的运行查看 Actions 日志。

来源健康与发布结果分开读：`fresh` 为本次通过，`retained-last-good` 为旧基线，`unavailable-no-baseline` 为不可用；发布 `PASS` 不代表所有来源抓取成功。

## 依赖与身份

Dependabot 每周检查 Actions / HTTPS 依赖，每组最多一个 PR，允许跨大版本。只有同仓可信机器人、限定文件、精确 SHA 的 Linux / Windows CI 全通过且包含当前 `main` 才能快进。特权流程不执行 PR 代码；并发变化等待重测。

`check_git_identity.py` 检查可达提交的作者与提交者，不验证登录账号；提交前另运行 `--current-only`。凭据不得写入仓库或日志。
